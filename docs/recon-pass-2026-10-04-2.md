# External reconnaissance — 2026-10-04, pass 2

This pass intentionally looked beyond the already-reviewed LunaGC and string-literal tooling.

## High-value leads

### Historical obfuscated protobuf recovery

`partypooperarchive/ObfProtoDecoder` is old, but methodologically important. It reconstructs protobuf structure from partially obfuscated generated assemblies by using generated-code invariants rather than semantic names: field-number constants, backing fields/properties, generic container fields and oneof discriminator structure.

This suggests a useful current-version research direction: recover richer 7.1 message structure from canonical metadata/native artifacts, then validate it independently against parser/write/size methods and runtime wire observations.

The historical project is AGPL-3.0. Do not copy implementation into the Apache-2.0 repository; independently reproduce only the underlying method.

### Token-based packet recovery

`partypooperarchive/TokenRecovery` historically indexed packet classes by metadata token and CmdId. Modern metadata tokens/type indexes must not be assumed stable across versions, but the broader lesson is useful: retain structural identities in addition to obfuscated names so cross-build candidates can be compared mechanically.

A modern replacement should use multi-feature structural fingerprints rather than token equality.

### Kaitai schema generation

`partypooperarchive/KSysha` generated Kaitai Struct definitions for Genshin data types. The specific tool is historical, but the declarative-schema idea is useful for binary/resource formats: once a format is understood, encode the layout in a machine-readable schema or compact parser contract instead of preserving only reverse notes.

### Lua format recovery

`Project-x64/genshin-luadec` records that Genshin's Lua variant historically changed headers/opcode ordering. This remains a navigation lead for Scene/Quest/activity script research. Prefer current extracted/decompiled script resources when available; only reopen bytecode-format work if a concrete current-version consumer appears.

### Current generic IL2CPP tooling

Recent generic IL2CPP dumpers increasingly expose machine-readable/LLM-oriented JSON, method RVAs, type graphs and runtime dump paths. They are not trusted Genshin 7.1 decoders, but their output-design lesson is relevant: analysis artifacts should be queryable and split by stable identities instead of requiring humans to grep giant `dump.cs` files.

Genshin-Reverse already follows much of this principle through canonical CSV/JSON metadata. Do not add another duplicate dump format unless it closes a concrete query gap.

## Conclusions

1. The strongest new opportunity is structural protobuf recovery, especially oneof/container/message-type relationships.
2. Cross-version matching should use a composite fingerprint, never a single metadata token/index.
3. Declarative binary schemas are worth using after a format is stable, but are not a priority without a current AstaPS consumer.
4. Current generic dumpers offer UX ideas, not canonical evidence.
5. Old reverse tools remain useful when they reveal invariants; version-specific constants and mappings remain historical-only.
