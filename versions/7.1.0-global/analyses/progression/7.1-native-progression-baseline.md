`AvatarExtraLevelExcelConfigData.json` (blob `4c8fc8bcd051e2686eeb8e202f20cbecf73be453`) has two records: `DEJBOJMHHJB` contains 90/95, `BBPEGJLEEEC` contains 95/100, and both use material ID `104300` in `costItems` with amounts 1/2. **Large-table retrieval note:** `ProudSkill`, `WeaponPromote`, and `ReliquaryExcel` are **populated** at the pinned commit (respectively 6,273; 1,814; and 4,352 rows), confirmed by fetching Git blobs directly. Path-based file retrieval can return no text for large files despite nonempty blob SHA values. Do not interpret such connector output as an empty source table.

## Level-up Mora rule

Evidence: `B`.

Grasscutter's avatar-upgrade path reads `ITEM_USE_ADD_EXP`, computes the total EXP supplied by the selected books, then charges:

```
moraCost = expGain / 5
```

This matches the native ratio of 1 Mora per 5 supplied character EXP, but it has not yet been rebound to a 7.1 native client rule/table.

For exactly 8,362,650 required EXP, the theoretical Mora-equivalent is 1,672,530.

Important: an actual book combination can oversupply EXP, so the paid Mora can differ slightly depending on the exact items consumed. Keep "raw curve cost" separate from "operational book-feed cost".

## Character mapping model

Evidence: `A`.

The native chain is:

`AvatarExcelConfigData.id`
-> `avatarPromoteId`
-> `AvatarPromoteExcelConfigData.avatarPromoteId`
-> stage-specific `costItems`, `scoinCost`, level cap and ascension-stat additions.

`AvatarExcelConfigData` also supplies `qualityType`, base stats, `propGrowCurves`, `skillDepotId`, and weapon type.

Do not collapse all 4-star or all 5-star characters into a single stat template. Material IDs and ascension-stat growth remain keyed by character/promote group.

### Complete weapon-to-promotion source map (2026-10-14)

[The source-row snapshot](weapon/7.1-weapon-promote-map.json) links all **287**

### Weapon exceptions and missing source IDs

A previous resource scan described certain groups as having "empty material
arrays". On closer inspection, **nine groups actually contain positive
material counts but no item IDs** in their pinned JSON:

- 4-star IDs `11419 / 11420 / 11421 / 11429 / 14411`;
- 3-star IDs `12304 / 13304 / 14306 / 15306`.

Across those nine groups are **162 unknown-ID material slots**, represented
explicitly with `itemId: null` and the original count. Guessing material IDs
from another weapon's rarity template is not valid source evidence.
`14411` itself has no referencing weapon in this snapshot, although weapon
`14411` points at shared group `11101`.

By contrast, **group `11521` has genuinely zero material counts and zero
promotion Mora** in all six paid-stage rows. Ten other groups have only
0–4 stages, mostly low-rarity and shared configurations. These remain source
observations, not verified client-upgrade outcomes.

Regenerate with `python scripts/collect-7.1-weapon-growth.py --resources
/path/to/AstaPS-Resource/ExcelBinOutput --check` from the pinned source
checkout. Weapon payment semantics, missing-ID recovery and actual availability
still require separate evidence.
