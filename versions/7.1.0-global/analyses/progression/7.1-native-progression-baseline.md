## Level-up Mora rule

Evidence: `B`.

Grasscutter's avatar-upgrade path reads `ITEM_USE_ADD_EXP`, computes the total EXP supplied by the selected books, then charges:

```
moraCost = expGain / 5
```

This matches the native ratio of 1 Mora per 5 supplied character EXP, but it has not yet been rebound to a 7.1 native client rule/table.

For exactly 8,362,650 required EXP, the theoretical Mora-equivalent is 1,672,530.

Important: an actual book combination can oversupply EXP, so the paid Mora can differ slightly depending on the exact items consumed. Keep "raw curve cost" separate from "operational book-feed cost".

## Character mapping model

Evidence: `A`.

The native chain is:

`AvatarExcelConfigData.id`
-> `avatarPromoteId`
-> `AvatarPromoteExcelConfigData.avatarPromoteId`
-> stage-specific `costItems`, `scoinCost`, level cap and ascension-stat additions.

`AvatarExcelConfigData` also supplies `qualityType`, base stats, `propGrowCurves`, `skillDepotId`, and weapon type.

Do not collapse all 4-star or all 5-star characters into a single stat template. Material IDs and ascension-stat growth remain keyed by character/promote group.

### Weapon exceptions

Do not infer a weapon's native cost schedule from `rankLevel` alone.

The 7.1 table contains special/test/quest-like entries whose `weaponPromoteId` points to a truncated or zero-material promote group, including some nominal 4-star and 5-star entries. The dominant normal patterns above cover 24 3-star groups, 143 4-star groups, and 74 5-star groups in the current data scan.

When generating a complete weapon baseline, resolve each weapon through its actual `weaponPromoteId` and preserve exceptions instead of forcing every same-rarity weapon onto the dominant template.

### Initial substats and enhancement checkpoints

`ReliquaryExcelConfigData.json` contains separate normal 5-star item variants with:

- `appendPropNum = 3`
- `appendPropNum = 4`

For the inspected pair, both have artifact-config `weight = 1`.

Do not yet convert that into a final 50/50 drop probability: the reward/drop table may weight the two artifact IDs before the artifact configuration is consulted.

5-star rows have:

`addPropLevels = [5, 9, 13, 17, 21]`

Because displayed +0 is internal level 1, these correspond to displayed enhancement checkpoints:

**+4 / +8 / +12 / +16 / +20**

A 3-initial-substat artifact uses the first checkpoint to add the fourth substat; later checkpoints upgrade an existing substat. A 4-initial-substat artifact upgrades an existing substat at every checkpoint.

### Mora and enhancement multipliers

Matching server behavior remains evidence `B`:

- artifact enhancement Mora is approximately 1 Mora per 1 artifact EXP fed;
- enhancement EXP multiplier distribution is 90% x1, 9% x2, 1% x5.

The 270,475 EXP requirement, main-stat weights, substat weights/roll values, initial-substat variants, and +4/+8/+12/+16/+20 checkpoints are now directly bound to current 7.1 Reliquary tables and are evidence `A`.
