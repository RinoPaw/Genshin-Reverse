## Research home and regeneration

**Home:** `RinoPaw/Genshin-Reverse@main`, this directory. Keep data acquisition,
source identity, extractors, and evidence here. `RinoPaw/AstaPS-Resource` is
the upstream **source-data checkout**; `RinoPaw/AstaPS` is the **implementation
consumer**. Do not move native claims into AstaPS merely because its code has
a similar rule.

The two character/talent collectors require the *unaltered* `ExcelBinOutput`
files from `RinoPaw/AstaPS-Resource@b0f3a2791607cab2a4c24cb9ef249dd2d94d7ffd`.
Their SHA checks fail closed when the wrong revision or an edited file is supplied:

```bash
python scripts/collect-7.1-avatar-growth.py --resources /path/to/ExcelBinOutput --check
python scripts/collect-7.1-talent-costs.py --resources /path/to/ExcelBinOutput --check
python scripts/collect-7.1-dungeon-previews.py --resources /path/to/ExcelBinOutput --check
python -m unittest tests.test_avatar_growth_snapshot tests.test_talent_cost_snapshot tests.test_dungeon_reward_previews
```

The 167 avatar rows include test, unreleased, and non-formal entries; **132 are
marked `AVATAR_FORMAL`**, which is still not by itself a verified playable
roster. The avatar mapping uses the primary depot; the talent map separately
includes every depot, so Traveler elemental variants are not accidentally
omitted. Neither snapshot proves talent-upgrade packet behavior, weight
probabilities, or the game's runtime selection of active skill depots.
