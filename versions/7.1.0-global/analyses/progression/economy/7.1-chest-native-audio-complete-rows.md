# Global 7.1 宝箱音频分类：原版行解析与公开标签关联

**2026-10-21 · Issue [#31](https://github.com/RinoPaw/Genshin-Reverse/issues/31)**

**当前结论：原版音频表 56 行、480 字节完整解析；56 个原始 Gadget 键与公开 CN 7.1 的分类标签逐行一致。奖励等级、场景实例及服务器掉落仍未证实。**

## 原生来源与读取流程

1. 官方 Global 7.1 Sophon `00/25539185.blk`（完整来源校验见 [原版资产索引报告](7.1-chest-lv3-original-index.md)）导出 `5560e262.dat`，原始 SHA-256 为 `c205c6d4efe69fde2b88800802816afd981a94df35e768746f5692e74febe591`，去掉 MiHoYoBinData 长度帧后为 **480 字节**，载荷 SHA-256 为 `a59a480b86a0fcb85d7b0e4d72f631d1b78b6e2d87b58ac579c91ec4a9147257`。
2. 原版 EXE SHA-256 `08a3086d5f3fe695f01dab61efa42e442006b18e5e475b2520df356f6a073b7d` 中，候选表加载器位于 RVA `0x130156D0`，以 `0x81F9C781 XOR header` 读取原版 **56** 行，并在 `0x130157AC` 经 vtable `+0xF0` 调用每行读取器。
3. 原版 IL2CPP type definition **36519** (`LAGPEMOIAKN`) 的候选方法 **287887**、RVA `0x77C01B0` 使用两个可选原生字段。行 mask 由 `(wire_u16 XOR 0xFFFFE5C7) + 0xFFFFEE77` 得到；bit `0x20` 对应一个 uint32 数值，bit `0x10` 对应 Gadget 键经本机写包装器 `0xBB16020` 处理前的 uint32 值。
4. 原版读取器逻辑不借助社区 JSON 的字段内容即可连续解析 **56/56 行，480/480 字节，尾部剩余 0 字节，Gadget 键无重复**。有 21 行只有 `0x10` 标志，35 行同时具有 `0x10/0x20` 标志。其原始字段数值为：缺省 21 行，`1` 为 12 行，`2` 为 12 行，`3` 为 11 行。

原版完整读取成功：[Actions #39586611284](https://github.com/RinoPaw/Genshin-Reverse/actions/runs/39586611284)。重现器：`scripts/audit-7.1-chest-audio-native-rows.py`；无须客户机的合成回归测试：`tests/test_chest_audio_native_rows_71.py`。

## 56 个原版值与公开 CN 7.1 逐键对齐

公开数据来自 [DimbreathBot/AnimeGameData@792978e](https://github.com/DimbreathBot/AnimeGameData/blob/792978e5503ecfba73dcb3562ed44a0d35a2abe2/ExcelBinOutput/AudioBattleFervorChestTypeMapConfigData.json)，原始 Git blob `f2f2f9c05e6333a9dc302b11a1bc39e16f621f5f`。其 `AIMCCDKDAKB` 和 `DMNAJDGMHDE` 是公开数据的字段名猜测；在原版 IL2CPP 元数据中的确有对应的两个唯一字段 token，但来源 JSON 的字符串仍是单独的证据层。

| 原版 uint32 / 字段情况 | 公开标签 | 完全对应的 Gadget 键数量 |
| --- | --- | ---: |
| 缺省 | 缺省 | 21 |
| `1` | `Mid` | 12 |
| `2` | `Hi` | 12 |
| `3` | `Top` | 11 |

**全部 56 个原生键与公开键一一吻合，分类值关联 0 个冲突。** 原版 `SceneObj_Chest_{Default,Locked,Bramble,Frozen}_Lv3` 四个 ID `70210031–70210034` 在该表中均为数值 **1**；对应的四个 Lv4 和 Lv5 定义分别取 2 和 3。这些 ID 和原生值直接来自经验证的原始二进制。标签拼写 `Mid/Hi/Top` 来自公开 CN 7.1 投影。

逐键来源验证：[Actions #39587278416](https://github.com/RinoPaw/Genshin-Reverse/actions/runs/39587278416)，常规 CI 同时通过。复现脚本 `scripts/audit-7.1-chest-audio-public-association.py` 首先检查公开 Git blob 与原版完整行报告指纹，再逐键对齐原始整数和公开字符串；相关测试在 `tests/test_chest_audio_public_association_71.py`。永久机器摘要见 [JSON](7.1-chest-native-audio-complete-rows.json)，其中包含 source SHA、56 行消费状态、按值聚合及 Gadget 键序列 SHA-256。

## 尚未证明的语义

- 原版运行时类指针与实际虚函数表 `+0xF0` 行读取器的最终注册绑定；原版 56 行完全消费和字段偏移吻合提供强结构证据，但无法独立证明这个绑定。
- 原生 Gadget 键写入包装器 `0xBB16020` 与读取器 `0xBB15F50` 的运行时替换表与来回转换；表中目前报告**包装前键值**。
- `Mid`、`Hi`、`Top` 的官方枚举符号、原版音频业务如何使用它们，以及它们是否对应任何宝箱奖励档次。
- `InvestigationTargetConfigData` 的完整原版 252 行反序列化；已证实原生表加载器行数与直接行读取调用 RVA `0x151E96800`，仍需单独完整字段验证。
- 实际宝箱 `scene/group/config` 放置来源、服务器 `drop_tag`、`chest_drop_id`、奖励根节点、物品数量和概率。

**禁止用这个音频分类映射生成 LootCSS 奖励规则。AstaPS 奖励数值未改动。**
