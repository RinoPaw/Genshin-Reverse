# Original Global 7.1 chest Lv3 scope boundary

Investigated: 2026-10-21. Status: **original Gadget definitions verified; Lv3 placement, quality and payout semantics unresolved**.

The [SHA-256-pinned original-client Gadget audit](7.1-chest-native-gadget-prefab-controls.json) confirms 20 core definitions: `SceneObj_Chest_{Default,Locked,Bramble,Frozen}_Lv1..Lv5`. Each name is a literal string from the exact Global 7.1 Gadget asset. `Lv` is a *name suffix*, not an established official reward quality.

The separate historical server-source scanner [`scripts/audit-7.1-legacy-chest-sources.py`](../../../../scripts/audit-7.1-legacy-chest-sources.py) deliberately accepts only `Lv[1245]` for its four-grade census. A direct, fail-closed comparison of **these 20 source-pinned core definitions** gives:

| Original Gadget name suffix | Core definitions | Matched by historical four-grade filter |
| --- | ---: | ---: |
| `Lv1` | 4 | 4 |
| `Lv2` | 4 | 4 |
| `Lv3` | **4** | **0** |
| `Lv4` | 4 | 4 |
| `Lv5` | 4 | 4 |
| Total | **20** | **16** |

The excluded original IDs are **70210031**, **70210032**, **70210033** and **70210034**, respectively named `Default`, `Locked`, `Bramble` and `Frozen` with `_Lv3`. The comparison is limited to the 20 verified controls, not all 309 client native type-26 definitions or world-placed chest objects. This is a **source selection boundary**, not evidence that there are zero `Lv3` placements or that `Lv3` names imply a particular in-game chest grade.

Reproduce directly from the checked-in source-pinned controls and the original historical regex:

```sh
python scripts/audit-7.1-chest-lv3-scope.py
python -m unittest discover -s tests -p 'test_chest_lv3_scope_71.py' -v
```

The audit checks asset identity, exact core ID/name combinations, duplicate keys, and current regex inclusion. Changing the historical filter to include `Lv3` deliberately fails its regression check until the changed scope is reviewed.

**Next source gate:** prove the `Lv3` instance population, independently establish what this suffix means in the original client, and find a 7.1-authenticated scene/claim owner. Do not assign one of the four standard reward grades from the suffix or historical regex alone. The client asset and historical `drop_tag`, `chest_drop_id`, server roots, quantities and item weights retain separate provenance. Nothing here changes AstaPS Loot configuration or validates any 7.1 reward probability.
