# Original Global 7.1: who owns world-chest placement?

Status: **UNRESOLVED**. Source scope: exact Global 7.1 original Windows client only. Question: does the client ship complete world-chest coordinates/scene-instance `level`, or does it receive these from an official server?

## What is now source-verified

- The exact official compressed Sophon manifest, original design asset index, original WorldArea-containing Unity bundle `00/24230448.blk`, and scene 3 WorldArea raw object have independent hashes; see [the native index/export coverage evidence](7.1-original-worldarea-design-index-export-coverage.json).
- The original design index maps **167,673** distinct 40-bit asset hash rows to this block. Original Raw export produces exactly **167,673** hashed `MiHoYoBinData` files (**415,672,040** bytes). All exported 32-bit filename stems correspond to an index row mapped to the same block: **167,667** unique-name matches and **6** 32-bit-name collisions with another index row. The original 40-bit identities distinguish these six cases; their 32-bit exported filenames cannot independently disambiguate the rows.
- Thirteen independently verified original WorldArea assets belong to the block. WorldArea describes area geometry; this does not identify chest placement.
- Original `GadgetExcelConfigData` contains 30,599 native decoded Gadget rows including 20 original chest-prefixed literal names. Direct little-endian u32 Gadget ID byte scanning fails its **known-positive original GadgetExcel source** (0/20 IDs detected despite all 20 decoded rows), and likewise yields zero in WorldArea block exports. The scan is **not a valid absence test** for original scene instances.
