## Candidate raw-export verification gate (2026-10-21)

The same read-only probe now optionally accepts --asset-export pointing at an exported
MiHoYoBinData directory from an exact-client block export, and --strict-exports.
Only HASH_RESOLVED candidates are eligible. It locates exportedName.dat,
checks the MiHoYoBinData length frame, records raw and unwrapped payload
SHA-256 plus group/block IDs, and flags missing or malformed exports explicitly.
A collision in the 8-character exported file stem is rejected instead of being
silently assigned to a candidate. No payload bytes or proprietary assets enter
the report, and nothing changes AstaPS rewards.

Example, executed from the Genshin-Reverse checkout:

    python scripts/probe-7.1-chest-native-assets.py --index-raw /path/to/7.1-design-index.raw --asset-export /path/to/extracted-block --strict-exports --output /tmp/7.1-chest-candidate-raw-manifest.json
    python -m unittest discover -s tests -p test_chest_native_asset_probe_71.py

The design-index digest is checked before scanning, with existing positive
Quest/Dungeon controls. The asset-export directory is **not independently
authenticated by that check**. Original 7.1 provenance needs pinned source
block bytes, block digest, exporter identity and derivation chain, followed by
a native row deserializer and full-byte-consumption validation. A raw hit is
still not evidence of chest drop roots, grades, random weights or any reward
ownership. This commit supplies the verification gate; it reports no
newly observed client asset results without the original raw input.
