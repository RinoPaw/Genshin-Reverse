The first two tiers additionally use the 1,000-EXP item through nested drop nodes. The last three tiers have the same character-EXP reward range.

For the highest native reward range, a raw 1 -> 90 requirement of 8,362,650 EXP implies a hard best/worst reward-range bound of:

- **62 runs** if every run yields 135,000 EXP;
- **77 runs** if every run yields 110,000 EXP.

The current 7.1 DropTable rows use `randomType = 1` and weight 10000 for each listed EXP component. A matching Grasscutter `DropSystem.calculateDropAmount` implementation treats `a;b` as a uniformly sampled inclusive integer range and evaluates all randomType-1 entries independently. This runtime interpretation is evidence `B`.

For the highest tier, that gives four equally likely raw EXP outcomes per base claim: **110k / 115k / 130k / 135k**, with mean **122,500 EXP**.

- Ratio-equivalent requirement: 8,362,650 / 122,500 = **68.27 claims**.
- Exact expected stopping time under the uniform-inclusive `B` semantics: **68.77 base claims** to reach or exceed the Lv.1 -> 90 EXP target.
- Expected Resin at 20 per claim: about **1,375 Original Resin**.

The hard reward-range bounds remain 62-77 claims, or **1,240-1,540 Original Resin**, before multi-claim/Condensed Resin rules.

## Source-bound Dungeon previews (not drop distributions)

Evidence: `A` for these resource rows, **not** for live reward selection.

The pinned `DungeonExcelConfigData` table contains 307
`DUNGEON_DAILY_FIGHT` rows (104 talent / 104 weapon / 98 artifact / 1
unclassified) and 66 `DUNGEON_BOSS` rows. Of the 373 rows, 372 have a
`passRewardPreviewID` that joins exactly to
`RewardPreviewExcelConfigData.id`. Dungeon 5116 has no preview ID.

Every one of the 307 daily-fight rows stores `statueCostID = 106` and
`statueCostCount = 20`. This is the **configured source cost**, not yet
proof that AstaPS or the original client deducts it in every claim state.
Weekly Boss rows do not store the same cost pair; do not fill their Resin
price from this table.

The snapshots also retain `showLevel`, `limitLevel`, scene ID, subtype,
and individual reward-preview item IDs. `previewItems.count` is saved
unchanged as a *display value*, including fractional strings like `"0.33"`.
Missing counts must remain null. Neither preview membership nor a printed
count establishes drop-node weights, reward probability, guaranteed yield
or expected number of farming runs.
