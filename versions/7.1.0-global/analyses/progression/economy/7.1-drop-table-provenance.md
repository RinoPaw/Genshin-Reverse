Checked: 2026-10-13. Scope: the two **`Server/`** drop tables used by AstaPS, **not** the separately extracted `ExcelBinOutput/` tables.

## Consequence for missing 7.1 Dungeon roots

Compare against the source-pinned [7.1 Dungeon graph](7.1-domain-drop-links.json) extracted from `AstaPS-Resource@b0f3a2791607cab2a4c24cb9ef249dd2d94d7ffd`:

- 373 selected Dungeon records: **166** roots present, **140** referenced roots absent, **67** no root pointer.
- **0 of the 140** missing roots is present in LunaGC's April 2026 `Server/DropTableExcelConfigData.json`.
- Missing roots by `cityId`: `1: 4`, `4: 8`, `5: 36`, `6: 32`, `7: 32`, `8: 28`.
- A bulk replacement using this same historical dataset therefore restores **zero** missing root IDs.
- A missing root is not proof of zero rewards or a faulty Dungeon row. The source snapshots and client dump do not verify live claim selection.

The `ExcelBinOutput/DungeonExcelConfigData.json` used for 7.1 has its own separate import lineage. **Do not assume that a 7.1-labelled resources repository also refreshed its `Server/` drop tables.**

## Reproduce

With checkouts pinned to the full commits above, use the files directly. This script compares semantic JSON rather than formatting and checks the 140 missing links:

```python
import json
from collections import Counter
from pathlib import Path

asta = Path("/path/to/AstaPS-Resource")
luna = Path("/path/to/LunaGC-Resources")
reverse = Path("/path/to/Genshin-Reverse")

def load_ids(root, name):
    rows = json.loads((root / "Server" / name).read_text(encoding="utf-8"))
    indexed = {row["id"]: row for row in rows}
    assert len(indexed) == len(rows), "Duplicate drop node id"
    return indexed

tables = {}
for name in ("DropTableExcelConfigData.json", "DropSubTableExcelConfigData.json"):
    left, right = load_ids(asta, name), load_ids(luna, name)
    assert left == right, name
    tables[name] = right
    print(name, len(left), "same-ID identical rows")

link_file = reverse / "versions/7.1.0-global/analyses/progression/economy/7.1-domain-drop-links.json"
graph = json.loads(link_file.read_text(encoding="utf-8"))
missing = [d for d in graph["domains"] if d["rootStatus"] == "ROOT_MISSING"]
assert len(missing) == 140
assert not set(d["rootDropId"] for d in missing) & set(tables["DropTableExcelConfigData.json"])
print("Missing roots:", len(missing), "recovered from LunaGC:", 0)
print("Missing by cityId:", dict(sorted(Counter(d["cityId"] for d in missing).items())))
```

**Semantic checks:** walk every positive-weight child edge in the old main/sub graph for those 68 roots. All are complete DAGs in the historical tables, with no missing referenced drop nodes or cycles. Cross-join against pinned 7.1 `7.1-dungeon-reward-previews.json`, `DisplayItemExcelConfigData.json`, and `ReliquaryExcelConfigData.json`:

- All **20** artifact roots reach real `ITEM_RELIQUARY` IDs; their reachable `setId` sets **exactly equal** the previewed `ITEM_DISPLAY.param` set IDs.
- All **48** talent/weapon roots have reachable material item-family sets (`itemId // 10`) **exactly equal** to the corresponding 7.1 reward-preview material families. Their **42 distinct material leaf IDs** all occur in the current 7.1 `MaterialExcelConfigData.json`.
- Example: Dungeon `4480` references missing root `85153500`. Its 7.0 graph has **19 reachable drop nodes** (all absent in AstaPS 7.1) and 60 payable reliquary leaves, whose sets `10001, 10003, 15031, 15032` match the 7.1 preview exactly.

The matching identities make these **strong compatibility recovery candidates**, not verified 7.1-native quantity distributions or probabilities. The recovered weight/count numbers come from a dataset with an explicit **6.6 restoration history**. Keep the original Asta tables intact until each candidate has provenance labelling, runtime semantic checks, and inventory/claim integration tests. In particular, current `DomainStatueDropService` rejects artifact display IDs without a `DisplayItem.param → Reliquary.setId` mapping: adding 20 missing artifact roots alone will not make those claims payable.

**Reproduction inputs:** Use the two pinned Git revisions above and the research snapshot `7.1-domain-drop-links.json`. Parse both main and sub JSON files into unique `id` maps, compute old-only/shared/changed IDs, intersect 7.1 `ROOT_MISSING.rootDropId` with the old main-node IDs, then recursively resolve children across the union of the old main and sub tables. Resolve leaf item families against the pinned 7.1 preview, DisplayItem, Reliquary and Material tables, rather than treating missing weights as zero or substituting previews as payables. The quantities are **not** cross-version-validated.

Unrecovered 72 roots cluster in `cityId` 7 (32) and 8 (28), plus twelve artifact roots in city IDs 1, 4, 6 (four each). They need a newer independently grounded source or explicitly labelled compatibility modelling.
