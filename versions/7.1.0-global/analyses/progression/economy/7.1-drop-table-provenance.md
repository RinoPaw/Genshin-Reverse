# 7.1 Dungeon DropTable provenance and cross-repository comparison

Checked: 2026-10-13. Scope: the two **`Server/`** drop tables used by AstaPS, **not** the separately extracted `ExcelBinOutput/` tables.

## Evidence and history

- `MeChen618/AstaPS-Resource` first introduced `Server/DropTableExcelConfigData.json` and `Server/DropSubTableExcelConfigData.json` in [`2d3d6fd2`](https://github.com/MeChen618/AstaPS-Resource/commit/2d3d6fd2fd29aa801efdd76e70de29f575b4bdc2), **2026-09-29**, labelled “Add Server and ScriptSceneData”. - `girluh/LunaGC-Resources` at [`d6c2c138`](https://github.com/girluh/LunaGC-Resources/commit/d6c2c13859386e8508ad958ac5f7e0d344c06892) also has those same two Git blobs. Shared content does **not** establish independent confirmation or the ultimate origin.

## Consequence for missing 7.1 Dungeon roots

Compare against the source-pinned [7.1 Dungeon graph](7.1-domain-drop-links.json) extracted from `AstaPS-Resource@b0f3a2791607cab2a4c24cb9ef249dd2d94d7ffd`:

- 373 selected Dungeon records: **166** roots present, **140** referenced roots absent, **67** no root pointer.
- **0 of the 140** missing roots is present in LunaGC's April 2026 `Server/DropTableExcelConfigData.json`.
- Missing roots by `cityId`: `1: 4`, `4: 8`, `5: 36`, `6: 32`, `7: 32`, `8: 28`.
- A bulk replacement using this same historical dataset therefore restores **zero** missing root IDs.
- A missing root is not proof of zero rewards or a faulty Dungeon row. The source snapshots and client dump do not verify live claim selection.

The `ExcelBinOutput/DungeonExcelConfigData.json` used for 7.1 has its own separate import lineage. **Do not assume that a 7.1-labelled resources repository also refreshed its `Server/` drop tables.**

## Reproduce

With checkouts pinned to the full commits above, use the files directly. This script compares semantic JSON rather than formatting and checks the 140 missing links:

```python
import json
from collections import Counter
from pathlib import Path

asta = Path("/path/to/AstaPS-Resource")
luna = Path("/path/to/LunaGC-Resources")
reverse = Path("/path/to/Genshin-Reverse")

def load_ids(root, name):
    rows = json.loads((root / "Server" / name).read_text(encoding="utf-8"))
    indexed = {row["id"]: row for row in rows}
    assert len(indexed) == len(rows), "Duplicate drop node id"
    return indexed

tables = {}
for name in ("DropTableExcelConfigData.json", "DropSubTableExcelConfigData.json"):
    left, right = load_ids(asta, name), load_ids(luna, name)
    assert left == right, name
    tables[name] = right
    print(name, len(left), "same-ID identical rows")

link_file = reverse / "versions/7.1.0-global/analyses/progression/economy/7.1-domain-drop-links.json"
graph = json.loads(link_file.read_text(encoding="utf-8"))
missing = [d for d in graph["domains"] if d["rootStatus"] == "ROOT_MISSING"]
assert len(missing) == 140
assert not set(d["rootDropId"] for d in missing) & set(tables["DropTableExcelConfigData.json"])
print("Missing roots:", len(missing), "recovered from LunaGC:", 0)
print("Missing by cityId:", dict(sorted(Counter(d["cityId"] for d in missing).items())))
```

## Remaining 72 roots and runtime ownership (2026-10-13)

The **72 not recovered** from the pinned historical 7.0 source can be identified exactly from the 7.1 `7.1-domain-drop-links.json` and the 68 historical matches above. Grouped by the source `cityId` (not by guessed region labels):

These are Dungeon IDs; their missing **root IDs** are the associated `rootDropId` values in the pinned graph. Do not confuse a Dungeon ID with a root ID or interpret absence as a configured empty reward.

**Verified server loading rule:** `RinoPaw/AstaPS@1c2cb794` declares `DropTableData` with `@ResourceType(name = {"DropTableExcelConfigData.json", "DropSubTableExcelConfigData.json"})`. Its `FileUtils.getExcelPath` searches `resources/Server/` first, then `resources/ExcelBinOutput/`, preferring TSJ over JSON over TSV *within each directory*. `ResourceLoader.loadFromResource` loads both named tables into the shared `GameData.getDropTableDataMap()`; therefore adding unique, structurally valid IDs to the `Server/` JSON tables would be consumed by the existing drop graph without inventing a separate `DungeonDrop.json` path. This does **not** prove that the game's original quantities, preview-family gate or inventory-claim path are correct. In particular, a deployed `Server/DropTableExcelConfigData.tsj` would take precedence over the JSON file.

**Patch safety:** an addition to either shared table may affect any consumer resolving that ID, not just a Dungeon claim. Require unique IDs across main/sub tables, positive-weight edge closure, acyclic graphs, valid leaf item identities, cross-checked reward families, and regression coverage for unrelated drop consumers. Preserve the four historical conflicting shared IDs rather than replacing existing rows. No data files are changed as part of this research note.

## Invoker-bot curated 7.1-compatible source (2026-10-14)

An additional cross-check used [`invoker-bot/LunaGC-Resources@e2c1d3c`](https://github.com/invoker-bot/LunaGC-Resources/tree/e2c1d3ca53ec7b6add27cf6f46ac9d1c377dc5f7), whose [README](https://github.com/invoker-bot/LunaGC-Resources/blob/e2c1d3ca53ec7b6add27cf6f46ac9d1c377dc5f7/README.md) explicitly describes a **curated cross-version** 7.1-centered collection using the 7.0 LunaGCR and 7.1 capyb sources. Its two `Server/` drop tables were introduced in [`b2132166`](https://github.com/invoker-bot/LunaGC-Resources/commit/b213216615ed91100cddfd544733aa2d561cdc08), dated 2026-09-29, not extracted with a documented official 7.1 drop-table tool.

Git blobs: main `812bdf7372b58d23887540682b910b1486ad3efa` (**13,921** rows), sub `5cb388a7089ebda4395681573fce8360c180e8f9` (**1,985** rows). Parsed JSON comparison with `AstaPS-Resource@2d3d6fd2` (13,823 main / 1,885 sub rows) gives:

- **98 new main IDs, 100 new sub IDs**; zero missing Asta IDs, zero different values at any shared ID across both tables.
- The same **68 of 140** missing Dungeon roots are recovered as in the historical LunaGCR 7.0 comparison; the same **72** remain missing. This is a *shared-data-lineage* check, **not** independent verification of native 7.1 rates.
- Walking every positive-weight node edge from those 68 root IDs through the invoker main+sub tables reaches **177 distinct drop nodes**, all absent from the current Asta tables: **83 main + 94 sub**. The induced referenced-node graph is acyclic, has no missing referenced *drop nodes*, and reaches **385 distinct terminal IDs**.
- **21 of the 198** additional invoker nodes are not reachable from the 68 target roots: **15 main, 6 sub**. A targeted compatibility import would therefore require only the 177 reachable IDs, not an indiscriminate copy of both complete tables.
- Invoker retained the existing Asta values at the four main IDs that differ in the original 7.0 dataset (`85333500, 85334000, 85334500, 85335500`). **None of these four changed historical nodes is reachable from the 68 recovered roots.**

Method: build unique `id` maps from each main/sub JSON, compute set differences and row equality on parsed objects, intersect the [source-pinned graph](7.1-domain-drop-links.json)'s `ROOT_MISSING.rootDropId` values with candidate main IDs, and depth-first traverse positive-weight child IDs present in the candidate node map. Treat references absent from both main and sub as *candidate terminal item IDs*, not automatically valid items; artifact and material identity checks are separately recorded above for the historical dataset. Compare *all* the candidate records before importing anything.

**Scope and limits:** This gives a **minimal no-ID-conflict compatibility patch candidate**, not a verified original-game 7.1 extraction. `countRange`, `randomType`, weights, terminal ItemData, the artifact preview/display mapping, and actual claim behavior still need validation in the deployed server. The resource tables were left unchanged.
