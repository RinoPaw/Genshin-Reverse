## Exact original aligned native method instructions (2026-10-21)

[Original-source disassembly run 39585765412](https://github.com/RinoPaw/Genshin-Reverse/actions/runs/39585765412) and [follow-up complete Audio row excerpt 39586029162](https://github.com/RinoPaw/Genshin-Reverse/actions/runs/39586029162) passed all source-hash and aligned-MOV/XOR instruction checks.

The **Audio** loader candidate entry at `0x130156D0` reads the count using `mov edi, 0x81F9C781` / `xor edi,[rax+rcx+0x20]`, checks `test edi,edi` at `0x1301576C`, then loops through row allocation and a virtual row-parser call **`[row.vtable+0xF0]` at `0x130157AC`**, fetching the row map key from native object offset **`0x14`** and calling key getter `0xBB15F50`. The counter decrements at `0x13015806` and jumps to the next row until zero. These native instructions **authenticate the original serialized header count of 56** independent of public JSON agreement, subject only to the already source-gated original 480-byte table binding.

The **Investigation** loader candidate entry at `0xB0128D0` follows the same native header-count, row-allocation and decrement-loop structure, with **252** rows confirmed by `xor edi, 0x6F0ECCD2` at `0xB01291E`. Its row parser uses a **direct call to RVA `0x151E96800` at `0xB0129A6`**, followed by a map-key read from offset **`0x18`**, wrapper getter `0xBB15F50`, and `dec edi` at `0xB0129FF`. A virtual-call-only scanner would miss this direct read path.

For Audio, original type-definition **36519** method **287887** (`LAGPEMOIAKN.GMENPOPMKAA`, RVA `0x77C01B0`) reads a 16-bit presence mask, decoded as **`((raw ^ 0xFFFFE5C7) + 0xFFFFEE77) mod 2^32`**. For bit `0x20`, it reads a uint32, adds `0x1520DAED` modulo `2^32` and writes field `+0x10`. For bit `0x10`, it reads a uint32, adds **`0x1C53C8D1`**, applies runtime wrapper `0xBB16020` and writes field **`+0x14`**. This matches the Audio table loader's `+0x14` key getter offset but is still **indirect evidence** of concrete vtable ownership.

The first original Audio row at payload offset 4 has raw mask `5e f4`: the native transform enables `0x10`, and the following encoded four-byte integer `00 89 db e7` plus `0x1C53C8D1` yields pre-wrapper key **70210001**. This is a direct source-byte/native-code crosscheck. A complete 56-row/EOF proof still requires replaying the recovered two-field reader over the full source asset. No string labels, client instance placements, server reward grades or payout quantities follow from these instruction anchors.
