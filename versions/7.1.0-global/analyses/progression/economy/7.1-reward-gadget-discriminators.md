# 原版 Global 7.1 客户端：Gadget 原生字段

研究范围：**只展示经过原版客户端二进制和原始数据共同验证的字段。** 本清单不使用历史 Lua、社区导出的 JSON、AstaPS、自定义地图标注及语言配置里的属性。原始字段含义尚未确认时，只写偏移和实际类型。

## 数据来源与验证范围

- 原版资源：Global 7.1 官方 Sophon 块 `00/25539185.blk`，导出 `GadgetExcelConfigData` 原始文件 `d65ab32f.dat`，SHA-256 `a35e3f3ed04f950cb6302099d12aa71e23ece21d8fe578950347d9318f769e35`；去外层帧后的数据 SHA-256 `b8f35d6f3fe1aec90398ccbbe205335fe0d9ae45245b206096be5e434746c354`。
- 读取代码由原版 EXE 逆向定位：继承字段读取器 RVA `0xBD56F60`，Gadget 字段读取器 RVA `0x10278E50`，表加载器 RVA `0x968F690`。二进制读取实现见 [`genshinre/gadgetbin.py`](https://github.com/RinoPaw/Genshin-Reverse/blob/main/genshinre/gadgetbin.py)。
- 对应的原版读取结果：[完整 30,599 行解析报告](7.1-chest-native-gadget-inner-row-audit.json)、[20 种原版宝箱字段样本](7.1-chest-native-gadget-prefab-controls.json)、[309 条数值 26 的名称分组](7.1-chest-native-gadget-type26-name-groups.json)。
- 原始表 **30,599/30,599 行**解析完成，数据载荷 **2,854,884/2,854,884 字节**消耗完成，尾部 0 字节未解析；一共 30,599 个不重复的包装前 Gadget 键。

下表的 `0x..` 是原版 IL2CPP 读取器中推导出的**候选内存字段偏移**，不是文件内固定字节位置。字段按存在位可选读取。字符串、整数、布尔值的类型来自该原生读取过程；除有直接内容证据者外，不替其编造游戏语义。

原版还完整验证了 `Default`、`Locked`、`Bramble`、`Frozen` × `Lv1..Lv5` 共 **20 个**对应名称/键组合。该组样本还直接解析出 `0x50="UI_Icon_Intee_TreasureBox"`、`0x84=2`，以及已存在的布尔字段 `0x78=true`、`0x7D=true`、`0x7E=true`。部分 `Lv1` 样本还包含 `0x48=["item"]`。

## 第二轮：完整原版字段组合交叉检查（Global 7.1）

本轮从上述 SHA-256 固定的原始 `d65ab32f.dat` 再次执行原生读取器，全表 30,599 条解析完成；核验记录见 [原生字段向量 JSON](7.1-native-gadget-field-vectors.json)，并由 [原版资源核查工作流](https://github.com/RinoPaw/Genshin-Reverse/actions/runs/39613533295) 验证。JSON 保留 `0x6C=26` 的 309 条完整已出现字段及存在位，并额外收录全表名称包含 `Chest`、但 `0x6C != 26` 的记录。所有分组依据都只是原生名称字符串的字面匹配。

| 原生字段/观察 | `SceneObj_Chest...` 前缀（162 条） | `SearchPoint...` 前缀（21 条） | 其他原生名称（126 条） |
| --- | ---: | ---: | ---: |
| `0x50 = UI_Icon_Intee_TreasureBox` | 129 | 0 | 36 |
| `0x50 = UI_Icon_Intee_Investigation` | 0 | 18 | 1 |
| `0x50 = UI_Icon_Intee_PickUp` | 16 | 3 | 29 |
| `0x60 = Default_Item` | 13 | 18 | 32 |
| `0x84 = 1` | 68 | 0 | 29 |
| `0x84 = 2` | 20 | 0 | 1 |
| `0x84 = 4` | 24 | 0 | 5 |
| `0x84` 原版序列化中缺失 | 50 | 21 | 91 |
| `0x7E` 已出现且为 `true` | 162 | 21 | 119 |

对全部 30,599 条记录按原生 `0x58` 名称检索，还发现 **31 条包含 `Chest` 的记录，其 `0x6C` 不等于 26**：值 `3` 有 5 条，`19` 有 16 条，`30` 有 3 条，`32` 有 2 条，`47` 有 2 条，`73` 有 3 条。例如原版字符串 `SceneObj_Chest_Default_Fake_Lv2` 对应 `0x6C=19`，`SceneObj_Chest_Hero_02` 对应 `0x6C=47`。这些原始值进一步说明，单凭 `0x6C` 或名称中的 `Chest` 都不能认定原版奖励种类。

**现阶段真正有实测区分能力的字段**包括原生对象名称 `0x58`、资源标识字符串 `0x50`、整数 `0x84`，以及部分布尔字段的存在情况；它们的具体游戏语义仍未验证。尤其 `0x84` 的 `1/2/4` 不能被擅自翻译成宝箱等级，`0x50` 图标字符串也不能被当作服务器掉落规则。每条记录的 `0x30` 保留包装前形式。
