## Goal and existing evidence

Support direct chest reward amounts in AstaPS `rewards.toml` with readable
region selectors, without introducing source routing, drop IDs or probability
fields into reward contents.

Continue, rather than repeat, the
[7.1 WorldArea native investigation](7.1-world-area-boundary-audit.md) and

## Proposed selector hierarchy (not yet a runtime contract)

Resolve the **chest gadget's own** `sceneID + position(x,y,z)`, never
the opening player's current area or a synthetic group's guessed nation.
The server area index should return `(sceneID,areaID1,areaID2)` with
`areaID2=0` when no verified child polygon matches. Derive the
`cityId` deterministically from the pinned level-1 crosswalk.

For a chest whose family has independently been identified:

1. `kind + scene + areaID1 + areaID2` exact override;
2. `kind + scene + areaID1` override;
3. `kind + cityId` override;
4. `kind` default.

Every matching table provides the **whole fixed reward**. No per-field
merging, no hardcoded item pools, and no `drop_tag`/drop-root control
fields in the TOML body. Example selector *syntax only* (the numbers do
not assert an approved reward-region boundary):

```toml
[chest."kind=common"]
adventureExp = 30
primogems = 2

[chest."kind=common,city=1"]
adventureExp = 30
primogems = 0

[chest."kind=common,scene=3,area1=10"]
adventureExp = 30
primogems = 2
```

An `area2` selector must validate its scene/parent membership.
Unknown/zero IDs are not wildcard values. Missing or invalid geometry,
gadget position, scene, or chest kind must be reported as unresolved;
do not silently award an exception-sensitive reward by guessing.

## Important limits before chest integration

**Native geometry:** the original 7.1 assets contain 90 parent polygons,
480 child polygon records for 474 distinct child IDs, and 9,177 vertices.
All 14 configured-but-unoutlined child IDs are also missing in original
7.1 WorldArea geometry. Eight changed scene-3 child IDs are
`5502, 5602, 5608, 5701, 5702, 5703, 5802, 5804`. A selector
using the current historical `AstaPS-Resource` geometry cannot claim
perfect original-7.1 boundary fidelity until these differences are
promoted into the resource consumed by AstaPS.

**Reward boundaries are not nation boundaries:** the available chest
reference distinguishes lower common/exquisite/precious Primogems
(`0/2/5`) in **most**, not all, old Mondstadt/Liyue areas from
higher `2/5/10` elsewhere. Exceptions include Stormbearer Mountains,
Dragonspine, Guyun Stone Forest, Lisha and The Chasm.
See https://genshin-impact.fandom.com/wiki/Chest .
The exact `scene/area1/area2` ID sets for these tiers **have not been
validated** by this audit. Do not activate a blanket `city=1` or
`city=2` low-tier rule without location-specific exceptions.
The Tsurumi remarkable-chest zero-Primogem exception needs a separate,
confirmed area mapping and actual remarkable-prefab attribution.

**Chest source/family:** the AstaPS full-scene audit found 14,084
ordinary scene gadget configurations, including 9,020 with `drop_tag`,
1,339 with an explicit drop ID, and 3,725 with neither. Several prefab
families are quests/one-off interactables; neither a positional lookup
nor `GadgetExcel.type=Chest` proves they should receive generic rewards.
A chest-position coverage run, filtered to genuine ordinary treasure
chests, has **not** been performed as part of this crosswalk.

**Double payout:** fixed `adventureExp` and `primogems` must replace,
not stack with, equivalent native drop-table leaves. Native random
items, furniture blueprints, quest state and confirmed claim success
remain separate responsibilities.
